ધ રસ્ટ પ્રોગ્રામિંગ લેંગ્વેજ (ગુજરાતી) - પ્રકરણ 1

Variables and Mutability

જે રીતે “variable સાથે મૂલ્યો સંગ્રહિત કરવા” વિભાગમાં ઉલ્લેખ કરવામાં આવ્યો છે, મૂળભૂત રીતે variable પરિવર્તનક્ષમ નથી હોતા. આ Rust દ્વારા આપવામાં આવતી ઘણી પ્રેરણાઓમાંની એક છે, જેથી તમે એવા કોડ લખો જે Rust આપેલી સલામતી અને સરળ સમવર્તમાનનો લાભ લે. તેમ છતાં, તમારી પાસે તમારા variable પરિવર્તનક્ષમ બનાવવાનો વિકલ્પ રહે છે. ચાલો જોઈએ કે Rust તમને અપરિવર્તનક્ષમતાને પ્રાધાન્ય આપવા માટે કેવી રીતે પ્રોત્સાહિત કરે છે અને શા માટે કેટલીકવાર તમે તેમાંથી મુક્તિ મેળવવા માગી શકો છો.

જ્યારે કોઈ variable અપરિવર્તનક્ષમ હોય, ત્યારે એકવાર મૂલ્ય નામ સાથે જોડાઈ જાય પછી, તમે તે મૂલ્ય બદલી શકતા નથી. આ સમજાવવા માટે, તમારા પ્રોજેક્ટ્સ ડિરેક્ટરીમાં cargo new variables નો ઉપયોગ કરીને “variables” નામનો નવો પ્રોજેક્ટ બનાવો.

પછી, તમારા નવા variable (variable) ડિરેક્ટરીમાં, src/main.rs ખોલો અને તેની કોડને નીચેના કોડ સાથે બદલો, જે હજી કમ્પાઇલ થશે નહીં:

ફાઈલનું નામ: src/main.rs

fn main() {
    let x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}

ચોક્કસ આદેશ ચલાવીને કાર્યક્રમ સાચવો અને ચલાવો: cargo run. તમને અપરિવર્તનશીલતાની ભૂલ (immutability error) સંબંધિત સંદેશ મળવો જોઈએ, જે આ પરિણામમાં દર્શાવેલ છે:

$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
error[E0384]: cannot assign twice to immutable variable `x`
 --> src/main.rs:4:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     println!("The value of x is: {x}");
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++

For more information about this error, try `rustc --explain E0384`.
error: could not compile `variables` (bin "variables") due to 1 previous error

આ ઉદાહરણ દર્શાવે છે કે કમ્પાઇલર તમને તમારા કાર્યક્રમોમાં ભૂલો શોધવામાં કેવી રીતે મદદ કરે છે. કમ્પાઇલરની ભૂલો નિરાશાજનક હોઈ શકે છે, પરંતુ હકીકતમાં તે માત્ર એટલું જ સૂચવે છે કે તમારો કાર્યક્રમ હજી સુરક્ષિત રીતે તમે જે ઇચ્છો છો તે કરી રહ્યો નથી; તેનો અર્થ એ નથી કે તમે સારા પ્રોગ્રામર નથી! અનુભવી Rustaceans પણ કમ્પાઇલરની ભૂલો મેળવે છે.

તમને cannot assign twice to immutable variable \x` એવો ભૂલ સંદેશ મળ્યો કારણ કે તમે અપરિવર્તનશીલx` variable બીજી કિંમત સોંપવાનો પ્રયાસ કર્યો હતો.

એ મહત્વનું છે કે જ્યારે આપણે એવા મૂલ્યને બદલવાનો પ્રયાસ કરીએ જે અપરિવર્તનશીલ તરીકે નિયુક્ત થયેલ છે, ત્યારે આપણને કમ્પાઇલ-ટાઇમ ભૂલો મળે, કારણ કે આ પરિસ્થિતિ જ bugs તરફ દોરી શકે છે. જો આપણા કોડનો એક ભાગ ધારે છે કે કોઈ મૂલ્ય ક્યારેય બદલાશે નહીં અને કોડના બીજા ભાગ દ્વારા તે મૂલ્ય બદલાય છે, તો એવું શક્ય છે કે કોડનો પહેલો ભાગ જે કરવા માટે ડિઝાઇન કરવામાં આવ્યો હતો તે ન કરે. આ પ્રકારની bug નું કારણ પકડવું મુશ્કેલ હોઈ શકે છે, વિશેષ કરીને જ્યારે કોડનો બીજો ભાગ મૂલ્યને માત્ર ક્યારેક જ બદલે છે. Rust કમ્પાઇલર ખાતરી આપે છે કે જ્યારે તમે જણાવો છો કે કોઈ મૂલ્ય બદલાશે નહીં, ત્યારે તે ખરેખર બદલાશે નહીં, તેથી તમારે તેની જાતે દેખરેખ રાખવાની જરૂર નથી. આથી તમારો કોડ સમજવામાં સરળ રહે છે.

પરંતુ પરિવર્તનક્ષમતા ઘણી ઉપયોગી થઈ શકે છે અને કોડ લખવામાં વધુ અનુકૂળ બનાવી શકે છે. ભલે variable (variable) મૂળભૂત રીતે અપરિવર્તનશીલ હોય, તમે તેને mut ઉમેરીને પરિવર્તનશીલ બનાવી શકો છો જેવું તમે પ્રકરણ ૨ માં કર્યું હતું. mut ઉમેરવાથી કોડના ભાવિ વાચકોને પણ ઈરાદો વ્યક્ત થાય છે કે કોડનો અન્ય ભાગ આ ચલનું મૂલ્ય બદલશે.

ઉદાહરણ તરીકે, ચાલો src/main.rs ને નીચે મુજબ બદલીએ:

ફાઈલ નામ: src/main.rs

fn main() {
    let mut x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}

હવે જ્યારે આપણે આ કાર્યક્રમ ચલાવીએ છીએ, ત્યારે આપણને આ પરિણામ મળે છે:

$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.30s
     Running `target/debug/variables`
The value of x is: 5
The value of x is: 6

આપણે x સાથે સંકળાયેલ મૂલ્યને 5 થી 6 માં બદલી શકીએ છીએ જ્યારે mut વપરાય છે. આખરે, પરિવર્તનશીલતા (mutability) વાપરવી કે નહીં તે નક્કી કરવાનું તમારા પર નિર્ભર છે અને તે વિશેષ પરિસ્થિતિમાં શું સ્પષ્ટ લાગે છે તેના પર આધાર રાખે છે.

Declaring Constants

અપરિવર્તનશીલ variable’s જેમ, અચળ પણ એક નામ સાથે જોડાયેલ મૂલ્ય હોય છે અને તેને બદલવાની મંજૂરી નથી, પરંતુ અચળ અને variable વચ્ચે થોડા તફાવત છે.

સૌ પ્રથમ, તમને અચળ સાથે mut વાપરવાની અનુમતિ નથી. અચળ માત્ર ડિફોલ્ટ રૂપે અપરિવર્તનશીલ જ નથી - તે હંમેશા અપરિવર્તનશીલ હોય છે. તમે let કીવર્ડને બદલે const કીવર્ડનો ઉપયોગ કરીને અચળ જાહેર કરો છો, અને મૂલ્યનો પ્રકાર દર્શાવવો આવશ્યક છે. આપણે આગલા વિભાગમાં, “ડેટા પ્રકાર” માં પ્રકારો અને પ્રકારની નોંધણી વિશે વાત કરીશું, તેથી અત્યારે વિગતોની ચિંતા કરશો નહીં. માત્ર એટલું જ જાણો કે તમારે હંમેશા પ્રકાર દર્શાવવો આવશ્યક છે.

Constants અચળ (constants) કોઈપણ અવકાશમાં જાહેર કરી શકાય છે, જેમાં વૈશ્વિક અવકાશ (global scope) પણ સામેલ છે, જે તેમને એવા મૂલ્યો માટે ઉપયોગી બનાવે છે જે કોડના ઘણા ભાગોને

જાણવાની જરૂર હોય છે. છેલ્લો તફાવત એ છે કે અચળને માત્ર એક અચળ અભિવ્યક્તિ (constant expression) પર જ સેટ કરી શકાય છે, રનટાઇમ (runtime) પર ગણતરી કરી શકાતા મૂલ્યના પરિણામ

પર નહીં. અહીં એક અચળ ઘોષણાનું ઉદાહરણ છે:

#![allow(unused)]
fn main() {
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;
}

અચળાંકનું નામ THREE_HOURS_IN_SECONDS છે, અને તેનું મૂલ્ય 60 (એક મિનિટમાં સેકન્ડની સંખ્યા) ને 60 (એક કલાકમાં મિનિટની સંખ્યા) વડે ગુણાકાર કરીને, અને પછી તેને 3 (આપણે આ કાર્યક્રમમાં ગણવા માંગતા હોઈએ તે કલાકોની સંખ્યા) વડે ગુણાકાર કરવાના પરિણામ પર સેટ કરવામાં આવ્યું છે. Rustનું અચળાંકો માટેનું નામકરણ ધોરણ એ કે બધા અક્ષરો મોટા મૂકે અને શબ્દો વચ્ચે અન્ડરસ્કોર વાપરવું. compilercompile time દરમિયાન અમુક ચોક્કસ ક્રિયાઓનું મૂલ્યાંકન કરી શકે છે, જેનાથી આપણે આ મૂલ્યને 10,800 પર સેટ કરવાને બદલે, સમજવામાં સરળ હોય અને ચકાસી શકાય તે રીતે લખવાનું પસંદ કરી શકીએ છીએ. અચળાંક મૂલ્યાંકન વિશે વધુ માહિતી માટે Rust Referenceના વિભાગ જુઓ, જેમાં કયા ક્રિયાઓનો ઉપયોગ કરી શકાય છે તેનું વર્ણન છે.

Constants variable અચળો સમગ્ર કાર્યક્રમ ચાલતો હોય ત્યાં સુધી માન્ય રહે છે, જે અવકાશમાં તે જાહેર કરવામાં આવ્યા હતા. આ ગુણધર્મ variable અચળોને તમારા એપ્લિકેશન ક્ષેત્રના મૂલ્યો માટે ઉપયોગી બનાવે છે, જે પ્રોગ્રામના બહુવિધ ભાગોને જાણવાની જરૂર પડી શકે છે, જેમ કે કોઈ રમતની ખેલાડીને કમાણી કરવાની મહત્તમ સંખ્યા અથવા પ્રકાશની

ગતિ. તમારા કાર્યક્રમમાં સમગ્ર જગ્યાએ વપરાતા હાર્ડકોડેડ મૂલ્યોને variable અચળ તરીકે નામ આપવું એ કોડના ભવિષ્યના જાળવણી કરનારાઓને તે મૂલ્યનો અર્થ સમજાવવામાં મદદરૂપ છે. જો ભવિષ્યમાં હાર્ડકોડેડ મૂલ્યને અપડેટ કરવાની જરૂર પડે તો તમારે તમારા કોડમાં માત્ર એક જ જગ્યાએ ફેરફાર કરવાની જરૂર પડશે.

Shadowing

જેમ તમે પ્રકરણ ૨ માં અનુમાન લગાવવાની ટ્યુટોરિયલમાં જોયું, તમે અગાઉના variable (variable) સાથે સમાન નામ ધરાવતું નવું variable જાહેર કરી શકો છો. Rust સમુદાયના લોકો કહે છે કે પ્રથમ variable બીજા દ્વારા છાયા પાડે છે, જેનો અર્થ એ થાય છે કે જ્યારે તમે ચલનું નામ વાપરો છો ત્યારે કમ્પાઇલર બીજું variable જોશે. અસરકારક રીતે, બીજું variable પ્રથમ variable ઢાંકી દે છે, જ્યાં સુધી તે પોતે છાયા ન પાડે અથવા અવકાશ સમાપ્ત ન થાય ત્યાં સુધી variable’s નામના કોઈપણ ઉપયોગો પોતાની તરફ ખેંચે છે. આપણે સમાન variable’s નામનો ઉપયોગ કરીને અને let કીવર્ડનો ફરીથી ઉપયોગ કરીને variable છાયા કરી શકીએ છીએ:

ફાઈલનામ: src/main.rs આ એક સરળ Rust કાર્યક્રમ છે જે “Hello, world!” છાપે છે.

fn main() { println!("Hello, world!"); }

આ કાર્યક્રમ main નામનું એક કાર્ય વ્યાખ્યાયિત કરે છે. આ કાર્ય Rust કાર્યક્રમનો પ્રવેશ બિંદુ છે. જ્યારે તમે કાર્યક્રમ ચલાવો છો, ત્યારે main કાર્ય પ્રથમ ચલાવવામાં આવે છે. println! એ એક macro છે જે કન્સોલ પર ટેક્સ્ટ છાપે છે. આ કિસ્સામાં, તે “Hello, world!” છાપે છે. તમે આ કાર્યક્રમને Rust compiler સાથે compile કરી શકો છો અને પછી executable બનાવી શકો છો. executable ચલાવવા માટે, તમે cargo run command વાપરી શકો છો.

fn main() {
    let x = 5;

    let x = x + 1;

    {
        let x = x * 2;
        println!("The value of x in the inner scope is: {x}");
    }

    println!("The value of x is: {x}");
}

આ કાર્યક્રમ સૌપ્રથમ x ને 5 ની કિંમત આપે છે. ત્યારબાદ, તે let x = નો ઉપયોગ કરીને એક નવું variable x બનાવે છે, અગાઉની કિંમત લઈને તેમાં 1 ઉમેરે છે જેથી x ની કિંમત 6 થાય. પછી, કદબદ્ધ કૌંસ {} વડે નિર્માણ પામેલા આંતરિક અવકાશમાં, ત્રીજું let વિધાન પણ x ને છાયા કરે છે અને એક નવું variable બનાવે છે, અગાઉની કિંમતને 2 વડે ગુણાકાર કરીને x ને 12 ની કિંમત આપે છે. જ્યારે તે અવકાશ પૂર્ણ થાય છે, ત્યારે આંતરિક છાયા સમાપ્ત થાય છે અને x તેની મૂળ કિંમત 6 પર પાછું ફરે છે. જ્યારે આપણે આ કાર્યક્રમ ચલાવીશું, ત્યારે તે નીચે મુજબનું પરિણામ આપશે:

$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/variables`
The value of x in the inner scope is: 12
The value of x is: 6

છાયા પાડવું એ variable mut તરીકે નિશ્ચિત કરવાથી અલગ છે, કારણ કે જો આપણે અજાણતાન ફરીથી કોઈ મૂલ્ય સોચવાનો પ્રયત્ન કરીએ તો આપણને કમ્પાઇલ-સમયની ભૂલ મળશે. let નો ઉપયોગ કરીને, અમે એક મૂલ્ય પર થોડા રૂપાંતરણો કરી શકીએ છીએ પરંતુ તે રૂપાંતરણો પૂર્ણ થયા પછી variable અપરિવર્તનશીલ રહે છે.

અન્ય તફાવત એ છે કે mut અને છાયા પાડવા વચ્ચે, કારણ કે આપણે let કીવર્ડનો ફરીથી ઉપયોગ કરતી વખતે અસરકારક રીતે એક નવું variable બનાવી રહ્યા છીએ, અમે મૂલ્યનો પ્રકાર બદલી શકીએ છીએ પરંતુ સમાન નામનો પુનઃઉપયોગ કરી શકીએ છીએ. ઉદાહરણ તરીકે, ધારો કે આપણું કાર્ય userને અમુક લખાણ વચ્ચે કેટલી જગ્યાઓ જોઈએ છે તે દર્શાવવા માટે કહે છે, જે જગ્યાના અક્ષરો ઇનપુટ કરીને, અને પછી અમે તે ઇનપુટને સંખ્યા તરીકે સંગ્રહ કરવા માંગીએ છીએ:

fn main() {
    let spaces = "   ";
    let spaces = spaces.len();
}

પહેલું spaces variable એક સ્ટ્રિંગ પ્રકારનું છે, અને બીજું spaces variable એક સંખ્યા પ્રકારનું છે. શૅડોઇંગથી આપણને અલગ નામો શોધવાની જરૂર પડતી નથી, જેમ કે spaces_str અને spaces_num; તેના બદલે આપણે સરળ spaces નામનો ફરી ઉપયોગ કરી શકીએ છીએ. જો કે, જો આપણે અહીં દર્શાવ્યા પ્રમાણે mut વાપરવાનો પ્રયત્ન કરીએ, તો આપણને કમ્પાઇલ-ટાઇમ ભૂલ મળશે:

fn main() {
    let mut spaces = "   ";
    spaces = spaces.len();
}

ભૂલ દર્શાવે છે કે આપણે ચલનું પ્રકાર બદલવાની અનુમતિ નથી.
