ધ રસ્ટ પ્રોગ્રામિંગ લેંગ્વેજ (ગુજરાતી) - પ્રકરણ 1

નમસ્તે, ક્રેટ!

Cargo એ Rustનું નિર્માણ તંત્ર અને પેકેજ વ્યવસ્થાપક છે. મોટાભાગના Rustaceans આ સાધનનો ઉપયોગ તેમના Rust પ્રોજેક્ટ્સનું સંચાલન કરવા માટે કરે છે, કારણ કે Cargo તમારા માટે ઘણાં કાર્યો સંભાળે છે, જેમ કે તમારા કોડનું નિર્માણ કરવું, તમારા કોડને જરૂરી હોય તેવા પુસ્તકાલયો (libraries) ડાઉનલોડ કરવા અને તે પુસ્તકાલયોનું નિર્માણ કરવું. (જે પુસ્તકાલયો તમારા કોડને જરૂર હોય છે તેને આપણે આધારભૂત (dependencies) કહીએ છીએ.)

આપણે અત્યાર સુધી જે સરળ Rust કાર્યક્રમો લખ્યા છે, તેમાં કોઈ આધારભૂત નથી. જો આપણે “Hello, world!” પ્રોજેક્ટ Cargo સાથે બનાવ્યો હોત, તો તે ફક્ત Cargoના તે ભાગનો ઉપયોગ કરત જે તમારા કોડનું નિર્માણ કરે છે. જેમ જેમ તમે વધુ જટિલ Rust કાર્યક્રમો લખશો, તેમ તેમ તમારે આધારભૂત ઉમેરવા પડશે અને જો તમે Cargoથી શરૂ કરીને કોઈ પ્રોજેક્ટ કરો છો, તો આધારભૂત ઉમેરવાનું ઘણું સરળ રહેશે.

કારણ કે મોટાભાગના Rust પ્રોજેક્ટ્સમાં Cargo વપરાય છે, આ પુસ્તકના બાકીના ભાગમાં એવું માનવામાં આવે છે કે તમે પણ Cargo વાપરી રહ્યા છો. જો તમે સત્તાવાર સ્થાપકોનો ઉપયોગ કર્યો હોય, તો Cargo Rust સાથે જ ઇન્સ્ટોલ થઈ જાય છે, જે “સ્થાપન” વિભાગમાં ચર્ચા કરવામાં આવી છે. જો તમે અન્ય કોઈ રીતે Rust સ્થાપિત કર્યું હોય, તો તમારા ટર્મિનલમાં નીચે મુજબ દાખલ કરીને તપાસ કરો:

$ cargo –version જો તમને આવૃત્તિ સંખ્યા દેખાય છે, તો તમારી પાસે તે છે! જો તમને કોઈ ભૂલ દેખાય છે, જેમ કે command not found, તો તમારા સ્થાપન પદ્ધતિ માટેના દસ્તાવેજો જુઓ જેથી કરીને કાર્ગોને અલગથી કેવી રીતે સ્થાપિત કરવું તે નક્કી કરી શકાય.

ક્રેટ સાથે પ્રોજેક્ટ બનાવવો cargo new <project_name> આદેશનો ઉપયોગ કરીને નવો ક્રેટ બનાવો. આ એક નવી ડિરેક્ટરી બનાવશે જે તમારા પ્રોજેક્ટનું નામ હશે. ઉદાહરણ તરીકે, “hello-world” નામનો પ્રોજેક્ટ બનાવવા માટે: cargo new hello-world આ આદેશ hello-world નામની ડિરેક્ટરી બનાવશે અને તેમાં જરૂરી ફાઇલો અને ફોલ્ડર્સ ઉત્પન્ન કરશે. તમે પછી ડિરેક્ટરીમાં જઈ શકો છો: cd hello-world હવે, તમે તમારા પ્રોજેક્ટના સ્ત્રોત કોડને src/main.rs ફાઇલમાં લખી શકો છો. cargo આપોઆપ જરૂરી ફાઇલ માળખું સેટ કરશે. તમે cargo build આદેશનો ઉપયોગ કરીને તમારા પ્રોજેક્ટને બનાવી શકો છો, અને cargo run આદેશનો ઉપયોગ કરીને ચલાવી શકો છો. જો કોઈ ભૂલ હોય, તો cargo તમને ચેતવણી આપશે.

ચાલો, કાર્ગોનો ઉપયોગ કરીને એક નવું પ્રોજેક્ટ બનાવીએ અને જોઈએ કે તે આપણી મૂળ “Hello, world!” પ્રોજેક્ટથી કેવી રીતે અલગ છે. તમારા પ્રોજેક્ટ્સ ડિરેક્ટરીમાં પાછા જાઓ (અથવા તમે તમારો કોડ ક્યાં સંગ્રહિત કરવાનું નક્કી કર્યું હોય ત્યાં). પછી, કોઈપણ ઓપરેટિંગ સિસ્ટમ પર, નીચે મુજબ ચલાવો:

$ cargo new hello_cargo $ cd hello_cargo પ્રથમ આદેશ એક નવું સંકેતક અને પ્રોજેક્ટ બનાવે છે જેનું નામ hello_cargo છે. આપણે આપણા પ્રોજેક્ટને hello_cargo નામ આપ્યું છે, અને Cargo તેનાં ફાઈલો એ જ નામના સંકેતકમાં બનાવે છે. hello_cargo

સંકેતકમાં જાઓ અને ફાઈલોની યાદી જુઓ. તમને દેખાશે કે Cargo એ આપણી માટે બે ફાઈલો અને એક સંકેતક ઉત્પન્ન કર્યો છે: એક Cargo.toml ફાઈલ અને એક src સંકેતક જેમાં main.rs ફાઈલ અંદર છે. તેણે એક

નવું Git ભંડાર પણ શરૂ કર્યું છે સાથે સાથે એક .gitignore ફાઈલનું. જો તમે cargo new આદેશનો ઉપયોગ વર્તમાન Git ભંડારમાં કરો છો, તો Git ફાઈલો ઉત્પન્ન થશે નહીં; તમે આ વર્તનને cargo new --vcs=git નો ઉપયોગ કરીને બદલી શકો છો.

નોંધ: Git એક સામાન્ય વર્ઝન નિયંત્રણ પ્રણાલી છે. તમે cargo new ને અન્ય વર્ઝન નિયંત્રણ પ્રણાલી અથવા કોઈ વર્ઝન નિયંત્રણ પ્રણાલી વાપરવા માટે --vcs ધ્વજ (flag) નો ઉપયોગ કરીને બદલી શકો છો. ઉપલબ્ધ વિકલ્પો જોવા માટે `cargo

new –help` ચલાવો. તમારી પસંદગીના ટેક્સ્ટ સંપાદકમાં Cargo.toml ખોલો. તે યાદી 1-2 માં આપેલ કોડ જેવું દેખાશે.

[package] name = "hello_cargo" version = "0.1.0" edition = "2024"

[dependencies] આ ફાઈલ TOML ( ટોમ્સ ઓબ્વિયસ, મિનિમલ ભાષા ) ફોર્મેટમાં છે, જે Cargo નું રૂપરેખાંકન ફોર્મેટ છે.

પ્રથમ લીટી, [package] , એક વિભાગનું નામ છે જે દર્શાવે છે કે નીચેના વિધાનો એક ક્રેટને રૂપરેખાંકિત કરી રહ્યા છે. જેમ આપણે આ ફાઈલમાં વધુ માહિતી ઉમેરીશું, તેમ તેમ અમે અન્ય વિભાગો પણ ઉમેરીશું.

આગામી ત્રણ લીટીઓ Cargo ને તમારા કાર્યક્રમને સંકલન કરવા માટે જરૂરી રૂપરેખાંકન માહિતી સેટ કરે છે: નામ, આવૃત્તિ અને ઉપયોગ કરવાના Rust નું આવૃત્તિ. આપણે edition કી વિશે Appendix E માં વાત કરીશું.

છેલ્લી લીટી, [dependencies] , એ એક વિભાગની શરૂઆત છે જ્યાં તમે તમારા પ્રોજેક્ટની નિર્ભરતાઓની યાદી આપી શકો છો. Rust માં, કોડના પેકેજોને ક્રેટ કહેવામાં આવે છે. આ પ્રોજેક્ટ માટે આપણને અન્ય કોઈ ક્રેટની જરૂર નથી, પરંતુ બીજા પ્રકરણમાં પ્રથમ પ્રોજેક્ટ માટે જરૂર પડશે, તેથી આપણે તે સમયે આ નિર્ભરતા વિભાગનો ઉપયોગ કરીશું.

હવે src/main.rs ખોલો અને એક નજર નાખો:

ફાઈલનું નામ: src/main.rs

fn main() { println!(“Hello, world!”); } કર્ગોએ તમારા માટે “Hello, world!” કાર્યક્રમ ઉત્પન્ન કર્યો છે, જેListing 1-1માં આપણે લખ્યો હતો તેના જેવો જ છે! અત્યાર સુધી, આપણા પ્રોજેક્ટ અને કર્ગોએ ઉત્પન્ન કરેલા પ્રોજેક્ટ વચ્ચેનો તફાવત એ છે કે કર્ગોએ કોડને src ડિરેક્ટરીમાં મૂક્યો છે, અને આપણી પાસે ટોચની ડિરેક્ટરીમાં Cargo.toml રૂપરેખાંકન ફાઇલ છે.

કર્ગો તમારા સ્રોત ફાઇલોને src ડિરેક્ટરીમાં રહેવાની અપેક્ષા રાખે છે. ટોચ-સ્તરના પ્રોજેક્ટ ડિરેક્ટરી ફક્ત README ફાઇલો, લાયસન્સ માહિતી, રૂપરેખાંકન ફાઇલો અને તમારા કોડ સાથે સંબંધિત ન હોય તેવી અન્ય વસ્તુઓ માટે છે. કર્ગોનો ઉપયોગ તમને તમારા પ્રોજેક્ટને ગોઠવવામાં મદદ કરે છે. દરેક વસ્તુ માટે એક સ્થાન છે, અને દરેક વસ્તુ તેની જગ્યાએ છે.

જો તમે એવી કોઈ યોજના શરૂ કરી હોય જે Cargo વાપરતી નથી, જેમ કે આપણે “Hello, world!” યોજનામાં કર્યું હતું, તો તમે તેને Cargo વાપરતી યોજનામાં ફેરવી શકો છો. તમારા યોજનાના કોડને src ડિરેક્ટરીમાં ખસેડો અને એક યોગ્ય Cargo.toml ફાઈલ બનાવો. આ Cargo.toml ફાઈલ મેળવવાનો એક સરળ રસ્તો એ છે કે cargo init ચલાવવું, જે આપમેળે તેને બનાવી દેશે.

ક્રેટ પ્રોજેક્ટનું નિર્માણ અને ચલાવીશઃ cargo નો ઉપયોગ કરીને, તમે તમારા પ્રોજેક્ટને સરળતાથી બનાવી અને ચલાવી શકો છો. rustup ઇન્સ્ટોલ કર્યા પછી, cargo આપમેળે જ ઇન્સ્ટોલ થઈ જાય છે. પ્રોજેક્ટ બનાવવા માટે, આદેશ વાપરો: cargo build આ આદેશ તમારા પ્રોજેક્ટના સ્ત્રોત કોડને સંકલિત (compile) કરે છે અને એક્ઝિક્યુટેબલ ફાઈલ બનાવે છે. સંકલન (compilation) દરમિયાન કોઈ ભૂલ (error) આવે તો, cargo તમને વિગતવાર માહિતી આપશે. પ્રોજેક્ટ ચલાવવા માટે, આ આદેશ વાપરો: cargo run આ આદેશ તમારા પ્રોજેક્ટને સંકલિત (compile) કરે છે અને પછી એક્ઝિક્યુટેબલ ફાઈલને ચલાવે છે. તમે cargo check આદેશનો ઉપયોગ કરીને ફક્ત સ્ત્રોત કોડની ચકાસણી પણ કરી શકો છો, જે ઝડપી છે કારણ કે તે એક્ઝિક્યુટેબલ ફાઈલ બનાવતું નથી. આ ખાસ કરીને મોટા પ્રોજેક્ટમાં ઉપયોગી છે. જો તમે કસોટીઓ (tests) ચલાવવા માંગતા હો, તો આ આદેશ વાપરો: cargo test cargo તમારા પ્રોજેક્ટની અંદર રહેલી તમામ કસોટીઓ (tests) શોધે છે અને તેમને ચલાવે છે. કસોટીઓના પરિણામો તમને દર્શાવવામાં આવશે, જેમાં કોઈ નિષ્ફળતા (failures) અથવા ચેતવણીઓ (warnings) શામેલ હોઈ શકે છે.

હવે આપણે જોઈએ કે જ્યારે આપણે Cargo વડે “Hello, world!” કાર્યક્રમ બનાવીએ અને ચલાવીએ ત્યારે શું ફેરફાર થાય છે. તમારા hello_cargo ફોલ્ડરથી, નીચેનો આદેશ દાખલ કરીને તમારી યોજના બનાવો:

$ cargo build Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo) Finished dev [unoptimized + debuginfo] target(s) in 2.85 secs આ આદેશ target/debug/hello_cargo (અથવા Windows પર target\debug\hello_cargo.exe) માં એક ચલાવવા યોગ્ય ફાઈલ બનાવે છે, તમારા વર્તમાન ડિરેક્ટરીમાં નહીં. કારણ કે ડિફૉલ્ટ બિલ્ડ એ ડીબગ બિલ્ડ છે, Cargo દ્વિસંગીને debug નામની ડિરેક્ટરીમાં મૂકે છે. તમે આ આદેશ સાથે ચલાવવા યોગ્ય ફાઈલ ચલાવી શકો છો:

$ ./target/debug/hello_cargo # or .\target\debug\hello_cargo.exe on Windows Hello, world! જો બધું સારું ચાલશે, તો Hello, world! ટર્મિનલ પર છાપાઈ જવું જોઈએ. પ્રથમ વખત cargo build ચલાવવાથી Cargo એક નવી ફાઈલ ટોચના સ્તરે બનાવે છે: Cargo.lock . આ ફાઈલ તમારા પ્રોજેક્ટમાં રહેલા આધારભૂત (dependencies) ઘટકોના ચોક્કસ સંસ્કરણોનો રેકોર્ડ રાખે છે. આ પ્રોજેક્ટમાં કોઈ આધારભૂત ઘટકો નથી, તેથી ફાઈલ થોડી ખાલી છે. તમારે ક્યારેય પણ આ ફાઈલ જાતે બદલવાની જરૂર નહીં પડે; Cargo તેના વિષમ પાત્રોનું વ્યવસ્થાપન તમારા માટે કરે છે.

અમે cargo build સાથે એક પ્રોજેક્ટ બનાવ્યો અને ./target/debug/hello_cargo વડે ચલાવ્યો, પરંતુ અમે cargo run નો ઉપયોગ કરીને કોડને સંકલિત (compile) કરી શકીએ છીએ અને પછી એક જ આદેશમાં પરિણામી એક્ઝિક્યુટેબલ ચલાવી શકીએ છીએ:

$ cargo run Finished dev [unoptimized + debuginfo] target(s) in 0.0 secs Running target/debug/hello_cargo Hello, world! cargo run વાપરવું એ cargo build ચલાવવા અને પછી બાઈનરીનો આખો માર્ગ વાપરવા કરતાં વધુ અનુકૂળ છે, તેથી મોટાભાગના વિકાસકર્તાઓ cargo run વાપરે છે. ધ્યાન કરો કે આ વખતે

અમને આઉટપુટ દેખાયું ન હતું જે દર્શાવે છે કે Cargo hello_cargo સંકલન કરી રહ્યું હતું. Cargo એ નક્કી કર્યું કે ફાઇલો બદલાઈ નથી, તેથી તેણે ફરીથી બનાવ્યું નહીં પરંતુ ફક્ત બાઈનરી ચલાવ્યું. જો તમે તમારા સ્રોત કોડમાં ફેરફાર કર્યો હોત, તો Cargo પ્રોજેક્ટને ચલાવતા પહેલા ફરીથી બનાવ્યો હોત, અને તમને આ આઉટપુટ દેખાયું હોત:

$ cargo run Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo) Finished dev [unoptimized + debuginfo] target(s) in 0.33 secs Running target/debug/hello_cargo Hello, world! કાર્ગો cargo check નામની એક આદેશ પણ આપે છે. આ આદેશ ઝડપથી તમારા કોડની ચકાસણી કરે છે કે તે સંકલિત થાય છે કે નહીં, પરંતુ એક્ઝિક્યુટેબલ ઉત્પન્ન કરતો નથી.

$ cargo check Checking hello_cargo v0.1.0 (file:///projects/hello_cargo) Finished dev [unoptimized + debuginfo] target(s) in 0.32 secs તમે ચલાવવા યોગ્ય ફાઈલ નથી ઇચ્છતા કેમ? ઘણીવાર, cargo check એ cargo build કરતાં ઘણું ઝડપી હોય છે કારણ કે તે ચલાવવા યોગ્ય ફાઈલ બનાવવાની પ્રક્રિયાને છોડી દે છે. જો તમે કોડ લખતી વખતે સતત તમારા કાર્યની તપાસ કરતા હોવ, તો cargo check નો ઉપયોગ કરવાથી તમને ખબર પડશે કે તમારો પ્રોજેક્ટ હજી પણ સંકલિત થઈ રહ્યો છે કે નહીં, તે જાણવાની પ્રક્રિયા ઝડપી થશે! આથી, ઘણા Rustaceans તેમના પ્રોગ્રામ લખતી વખતે સમયાંતરે cargo check ચલાવે છે જેથી ખાતરી થાય કે તે સંકલિત થાય છે. પછી, તેઓ જ્યારે ચલાવવા યોગ્ય ફાઈલનો ઉપયોગ કરવા તૈયાર હોય ત્યારે cargo build ચલાવે છે.

ચાલો આપણે અત્યાર સુધીમાં કાર્ગો વિશે જે શીખ્યા તેનું પુનરાવર્તન કરીએ:

આપણે cargo new નો ઉપયોગ કરીને એક પ્રોજેક્ટ બનાવી શકીએ છીએ.

આપણે cargo build નો ઉપયોગ કરીને પ્રોજેક્ટ બનાવી શકીએ છીએ.

આપણે cargo run નો ઉપયોગ કરીને એક જ પગલામાં પ્રોજેક્ટ બનાવી અને ચલાવી શકીએ છીએ.

આપણે cargo check નો ઉપયોગ કરીને પ્રોજેક્ટ બનાવી શકીએ છીએ, જે બાઈનરી ઉત્પન્ન કર્યા વિના ભૂલો માટે તપાસ કરે છે.

આપણા કોડની જેમ જ ડિરેક્ટરીમાં બિલ્ડનું પરિણામ સાચવવાની જગ્યાએ, કાર્ગો તેને target/debug ડિરેક્ટરીમાં સંગ્રહિત કરે છે.

Cargo વાપરવાના અન્ય એક લાભ એ છે કે આદેશો તમે જે ઓપરેટિંગ સિસ્ટમ પર કાર્ય કરી રહ્યા છો તેનાથી કોઈ ફરક પડતો નથી. તેથી, હવે પછી અમે Linux અને macOSની સરખામણીમાં Windows માટે ખાસ સૂચનાઓ આપવાનું બંધ કરીશું.

રિલીઝ માટે નિર્માણ

જ્યારે તમારી યોજના અંતિમ મુકાબજા માટે તૈયાર હોય, ત્યારે તમે તેને સુધારાઓ સાથે સંકલિત કરવા માટે cargo build --release નો ઉપયોગ કરી શકો છો. આ આદેશ target/release માં એક ચલાકીય વસ્તુ બનાવશે, target/debug ને બદલે. સુધારાઓ તમારી Rust કોડને ઝડપી બનાવે છે, પરંતુ તેમને ચાલુ કરવાથી તમારા કાર્યક્રમને સંકલિત થવામાં લાગતો સમય વધે છે. તેથી જ ત્યાં બે અલગ-અલગ રૂપરેખાઓ છે: એક વિકાસ માટે, જ્યારે તમે ઝડપથી અને વારંવાર ફરીથી બનાવવાનું ઇચ્છો છો, અને બીજો અંતિમ કાર્યક્રમ બનાવવા માટે જે વપરાશકર્તાને આપવામાં આવશે અને તેને વારંવાર ફરીથી બનાવવામાં આવશે નહીં અને તે શક્ય તેટલી ઝડપથી ચાલશે. જો તમે તમારા કોડના ચાલવાના સમયનું મૂલ્યાંકન કરી રહ્યા હો, તો cargo build --release ચલાવવાનું અને target/release માં ચલાકીય વસ્તુ સાથે મૂલ્યાંકન કરવાનું સુનિશ્ચિત કરો.

કર્ગોના સંમેલનોનો ઉપયોગ કરવો.

સરળ પ્રોજેક્ટ્સ સાથે, Cargo માત્ર rustc વાપરવા કરતાં વધારે લાભ આપતું નથી, પરંતુ જ્યારે તમારા કાર્યક્રમો વધુ જટિલ બનશે ત્યારે તે પોતાની કિંમત સાબિત કરશે. એકવાર પ્રોગ્રામ્સ અનેક ફાઇલો સુધી પહોંચે અથવા કોઈ આધાર રાખતી વસ્તુની જરૂર પડે, ત્યારે Cargo દ્વારા નિર્માણનું સંકલન કરાવવું ઘણું સરળ બની જાય છે.

જો કે hello_cargo પ્રોજેક્ટ સરળ છે, છતાં તે હવે ઘણાં વાસ્તવિક સાધનોનો ઉપયોગ કરે છે જેનો તમે તમારા Rust કારકિર્દીના બાકીના ભાગમાં ઉપયોગ કરશો. હકીકતમાં, કોઈપણ હાલના પ્રોજેક્ટ્સ પર કામ કરવા માટે, તમે Git નો ઉપયોગ કરીને કોડ તપાસવા, તે પ્રોજેક્ટની ડિરેક્ટરીમાં જવાનું અને નિર્માણ કરવા માટે નીચેના આદેશોનો ઉપયોગ કરી શકો છો:

$ git clone example.org/someproject $ cd someproject $ cargo build વધુ માહિતી માટે, Cargo નું દસ્તાવેજીકરણ તપાસો.

સારાંશ

તમારા Rust પ્રવાસની શરૂઆત ખૂબ જ સારી રીતે થઈ છે! આ પ્રકરણમાં, તમે શીખ્યા કે કેવી રીતે:

rustup નો ઉપયોગ કરીને Rust નું નવીનતમ સ્થિર સંસ્કરણ સ્થાપિત કરવું.

નવા Rust સંસ્કરણ પર અપડેટ કરવું.

સ્થાનિક રીતે સ્થાપિત દસ્તાવેજો ખોલવા.

rustc દ્વારા સીધું જ “Hello, world!” કાર્યક્રમ લખવો અને ચલાવવો.

Cargo ના સંમેલનોનો ઉપયોગ કરીને નવો પ્રોજેક્ટ બનાવવો અને ચલાવવો.

હવે વધુ મજબૂત કાર્યક્રમ બનાવવાનો આ સારો સમય છે, જેથી Rust કોડ વાંચવાની અને લખવાની ટેવ પડે. તેથી, પ્રકરણ ૨ માં, આપણે એક અનુમાન લગાવવાની રમત (guessing game) નો કાર્યક્રમ બનાવીશું. જો તમે સામાન્ય પ્રોગ્રામિંગ ખ્યાલો Rust માં કેવી રીતે કાર્ય કરે છે તે શીખવા માટે શરૂઆત કરવા માંગતા હો, તો પ્રકરણ ૩ જુઓ અને પછી પ્રકરણ ૨ પર પાછા ફરો.
