શરૂઆત

ચાલો તમારી Rustની યાત્રા શરૂ કરીએ! શીખવા માટે ઘણું છે, પરંતુ દરેક યાત્રા ક્યાંકથી જ શરૂ થાય છે. આ પ્રકરણમાં, આપણે ચર્ચા કરીશું:

Linux, macOS અને Windows પર Rust સ્થાપિત કરવું

એક પ્રોગ્રામ લખવો જે Hello, world! છાપે

cargo, Rustના પેકેજ મેનેજર અને બિલ્ડ સિસ્ટમનો ઉપયોગ કરવો

Installation

સ્થાપન Rust સ્થાપિત કરવા માટે, તમારે rustup નામનું સાધન વાપરવું પડશે. rustup એ Rust ના સંકલન (compiler), cargo (ક્રેટ નિર્માણ વ્યવસ્થાપક), અને અન્ય જરૂરી ઘટકોનું સંચાલન કરે છે. તમે rustup ને આ વેબસાઇટ પરથી ડાઉનલોડ કરી શકો છો: https://www.rust-lang.org/tools/install. ડાઉનલોડ કર્યા પછી, સ્થાપના સૂચનાઓનું પાલન કરો. મોટાભાગના કિસ્સાઓમાં, તમે ફક્ત સ્થાપક ચલાવીને અને પ્રક્રિયાને અનુસરીને પૂર્ણ કરી શકશો. સ્થાપન પછી, ખાતરી કરો કે rustc (Rust સંકલક) અને cargo તમારા PATH પર ઉપલબ્ધ છે. આ સામાન્ય રીતે સ્થાપન દરમિયાન આપમેળે થાય છે, પરંતુ જો તમને કોઈ સમસ્યા આવે તો તમારે તેને જાતે ગોઠવવાની જરૂર પડી શકે છે. તમે આદેશ વાક્યમાં rustc --version અને cargo --version લખીને ચકાસી શકો છો કે Rust યોગ્ય રીતે સ્થાપિત થયું છે કે નહીં. આ આદેશો Rust અને Cargo ના સંસ્કરણો પ્રદર્શિત કરશે.

સૌ પ્રથમ પગલું એ Rust સ્થાપિત કરવાનું છે. અમે rustup દ્વારા Rust ડાઉનલોડ કરીશું, જે Rust આવૃત્તિઓ અને સંલગ્ન સાધનોનું વ્યવસ્થાપન કરવા માટેનું કમાન્ડ લાઇન સાધન છે. ડાઉનલોડ માટે તમારે ઇન્ટરનેટ જોડાણની જરૂર પડશે.

નોંધ: જો તમે કોઈ કારણસર rustup વાપરવાનું પસંદ ન કરો, તો વધુ વિકલ્પો માટે કૃપા કરીને Other Rust Installation Methods પૃષ્ઠ જુઓ.

આગળના પગલાં Rust સંકલકની નવીનતમ સ્થિર આવૃત્તિ સ્થાપિત કરે છે. Rustની સ્થિરતા ખાતરીઓ સુનિશ્ચિત કરે છે કે પુસ્તકમાં આપેલા તમામ ઉદાહરણો જે compile થાય છે, તે નવા Rust વર્ઝન સાથે પણ compile થતા રહેશે. આઉટપુટ સંસ્કરણો વચ્ચે થોડું અલગ હોઈ શકે છે કારણ કે Rust ઘણીવાર ભૂલ સંદેશાઓ અને ચેતવણીઓમાં સુધારો કરે છે. બીજા શબ્દોમાં કહીએ તો, તમે આ પગલાંઓનો ઉપયોગ કરીને સ્થાપિત કરેલું Rustનું કોઈપણ નવું, સ્થિર સંસ્કરણ આ પુસ્તકની સામગ્રી સાથે અપેક્ષા મુજબ કાર્ય કરશે.

આદેશ વાક્ય સંકેત

આ પ્રકરણમાં અને સમગ્ર પુસ્તકમાં, અમે ટર્મિનલમાં વપરાતા કેટલાક આદેશો દર્શાવીશું. જે લીટીઓ તમારે ટર્મિનલમાં દાખલ કરવાની છે તે બધા $ થી શરૂ થાય છે. તમારે $ અક્ષર ટાઈપ કરવાની જરૂર નથી; તે દરેક આદેશની શરૂઆત દર્શાવવા માટે કમાન્ડ લાઇન પ્રોમ્પ્ટ છે. જે લીટીઓ $ થી શરૂ થતી નથી, તે સામાન્ય રીતે અગાઉના આદેશનું પરિણામ દર્શાવે છે. વધુમાં, PowerShell-વિશિષ્ટ ઉદાહરણો > નો ઉપયોગ કરશે તેના બદલે $ નો.

લિનક્સ અથવા મેકઓએસ પર rustup સ્થાપિત કરવું.

જો તમે લિનક્સ અથવા મેકઓએસ વાપરી રહ્યા છો, તો એક ટર્મિનલ ખોલો અને નીચેનો આદેશ દાખલ કરો:

$ curl –proto ‘=https’ –tlsv1.2 https://sh.rustup.rs -sSf | sh આદેશ એક સ્ક્રિપ્ટ ડાઉનલોડ કરે છે અને rustup સાધનનું સ્થાપન શરૂ કરે છે, જે Rust નું નવીનતમ સ્થિર સંસ્કરણ સ્થાપિત કરે છે. તમને તમારા પાસવર્ડ માટે પૂછવામાં આવી શકે છે. જો સ્થાપન સફળ થાય, તો નીચેની લીટી દેખાશે:

Rust is installed now. Great! તમને એક લિંકર પણ જરૂરી થશે, જે એક એવું કાર્ય છે કે જે Rust તેના સંકલિત પરિણામોને એક ફાઈલમાં જોડવા માટે વાપરે છે. શક્ય છે કે તમારી પાસે તે પહેલાથી જ હોય. જો તમને લિંકરની ભૂલો આવે, તો તમારે C સંકલક સ્થાપિત કરવો જોઈએ, જેમાં સામાન્ય રીતે લિંકરનો સમાવેશ થાય છે. C સંકલક એ પણ ઉપયોગી છે કારણ કે કેટલાક સામાન્ય Rust ક્રેટ્સ C કોડ પર આધાર રાખે છે અને તેમને C સંકલકની જરૂર પડશે.

macOS પર, તમે આ કાર્યકારી કમાન્ડ ચલાવીને C સંકલક મેળવી શકો છો:

$ xcode-select –install લિનક્સ વપરાશકર્તાઓએ સામાન્ય રીતે તેમના વિતરણની દસ્તાવેજીકરણ અનુસાર GCC અથવા Clang સ્થાપિત કરવું જોઈએ. ઉદાહરણ તરીકે, જો તમે Ubuntu વાપરતા હોવ, તો તમે build-essential પેકેજ સ્થાપિત કરી શકો છો.

વિન્ડોઝ પર rustup સ્થાપિત કરવું

વિન્ડોઝ પર, https://www.rust-lang.org/tools/install ની મુલાકાત લો અને Rust સ્થાપિત કરવા માટેની સૂચનાઓ અનુસરો. સ્થાપન દરમિયાન કોઈ તબક્કે, તમને Visual Studio સ્થાપિત કરવાનું કહેવામાં આવશે. આ એક લિંકર અને પ્રોગ્રામ્સને સંકલિત કરવા માટે જરૂરી મૂળ લાઇબ્રેરીઓ પૂરી પાડે છે. જો તમને આ પગલામાં વધુ મદદની જરૂર હોય, તો https://rust-lang.github.io/rustup/installation/windows-msvc.html જુઓ. આ પુસ્તકના

બાકીના ભાગમાં એવા આદેશોનો ઉપયોગ થાય છે જે cmd.exe અને PowerShell બંનેમાં કાર્ય કરે છે. જો કોઈ ચોક્કસ તફાવત હોય, તો અમે કયો વાપરવો તે સમજાવીશું.

મુશ્કેલીનિવારણ

તપાસ કરવા કે તમે યોગ્ય રીતે Rust સ્થાપિત કર્યું છે કે નહીં, તો એક શેલ ખોલો અને આ લીટી દાખલ કરો: `

$ rustc –version તમારે નવીનતમ સ્થિર આવૃત્તિ માટે સંસ્કરણ નંબર, કમિટ હેશ અને કમિટ તારીખ નીચેના ફોર્મેટમાં જોવી જોઈએ:

rustc x.y.z (abcabcabc yyyy-mm-dd) જો તમને આ માહિતી દેખાય, તો તમે સફળતાપૂર્વક Rust સ્થાપિત કર્યું છે! જો તમને આ માહિતી ન દેખાય, તો તપાસ કરો કે Rust તમારા %PATH% સિસ્ટમ ચલમાં નીચે મુજબ હાજર છે. વિન્ડોઝ

CMD માં, આનો ઉપયોગ કરો:

echo %PATH% પાવરશેલમાં, ઉપયોગ કરો:

echo $env:Path લિનક્સ અને મેકઓએસમાં, ઉપયોગ કરો:

$ echo $PATH જો આ બધું યોગ્ય હોય અને Rust હજી કાર્યરત ન થતું હોય, તો તમે મદદ મેળવી શકો તેવાં ઘણા સ્થળો છે. સમુદાય પાનાં પર અન્ય Rustaceans (આપણે આપણને આપેલા એક મૂર્ખ નામ)નો સંપર્ક કેવી રીતે કરવો તે જાણો.

સુધારણા અને અનિ સ્થાપન Rust ને સુધારવા માટે, rustup update આદેશ ચલાવો. જો તમે કોઈ ચોક્કસ Rust આવૃત્તિ પર પાછા જવા માંગતા હો, તો rustup install <version> નો ઉપયોગ કરો અને પછી rustup default <version> થી તેને ડિફૉલ્ટ તરીકે સેટ કરો. Rust ને અનિ સ્થાપિત કરવા માટે, rustup self uninstall આદેશ ચલાવો. આ તમારા સિસ્ટમમાંથી Rust, rustup અને cargo ને દૂર કરશે.

એકવાર Rust rustup દ્વારા સ્થાપિત થઈ જાય પછી, નવું પ્રકાશિત સંસ્કરણ અપડેટ કરવું સરળ છે. તમારા શેલમાંથી, નીચેની અપડેટ સ્ક્રિપ્ટ ચલાવો:

$ rustup update રસ્ટ અને rustup દૂર કરવા માટે, તમારા શેલમાંથી નીચેની અનઇન્સ્ટોલ સ્ક્રિપ્ટ ચલાવો:

$ rustup self uninstall

સ્થાનિક દસ્તાવેજીકરણ વાંચવું

રસ્ટનું સ્થાપન સ્થાનિક રીતે દસ્તાવેજનો નકલ પણ સામેલ કરે છે જેથી તમે તેને ઓફલાઈનમાં વાંચી શકો. તમારા બ્રાઉઝરમાં સ્થાનિક દસ્તાવેજ ખોલવા માટે rustup doc ચલાવો. જ્યારે પણ કોઈ પ્રકાર અથવા

કાર્ય પ્રમાણિત લાયબ્રેરી દ્વારા આપવામાં આવે અને તમને ખબર ન હોય કે તે શું કરે છે અથવા તેનો ઉપયોગ કેવી રીતે કરવો, તો માહિતી મેળવવા માટે એપ્લિકેશન પ્રોગ્રામિંગ ઈન્ટરફેસ (API) દસ્તાવેજનો ઉપયોગ કરો!

ટેક્સ્ટ સંપાદકો અને આદર્શ વાપરવા Rust કોડ લખવા માટે, તમે કોઈપણ ટેક્સ્ટ સંપાદકનો ઉપયોગ કરી શકો છો. જો કે, Rustના વિકાસને સરળ બનાવવા માટે ઘણાં આદર્શો (IDEs) ઉપલબ્ધ છે જે ખાસ કરીને Rust માટે રચાયેલાં છે. આ આદર્શો સામાન્ય રીતે કોડ પૂર્ણતા, સિન્ટેક્સ હાઇલાઇટિંગ અને ડીબગીંગ જેવાં કાર્યો પૂરાં પાડે છે. તમે rustup દ્વારા ઇન્સ્ટોલ કરેલાં આદર્શોનો ઉપયોગ કરી શકો છો અથવા તમે કોઈ અન્ય સંપાદક (editor) પસંદ કરી શકો છો. ઘણાં લોકપ્રિય સંપાદકો Rust માટે પ્લગઇન્સ (plugins) ધરાવે છે જે વિકાસની પ્રક્રિયાને વધારે છે. Rust પ્રોજેક્ટ્સ બનાવવા અને સંચાલિત કરવા માટે cargo એક શક્તિશાળી સાધન છે. આ cargo તમને crate બનાવવામાં, નિર્ભરતાનું સંચાલન કરવામાં અને compiler ચલાવવામાં મદદ કરે છે. linker પણ cargo દ્વારા સંચાલિત થાય છે. જો તમે નવા છો, તો તમે Visual Studio Code (VS Code) જેવાં આદર્શોનો ઉપયોગ કરવાનું વિચારી શકો છો, જેમાં Rust Analyzer નામનું એક સારું પ્લગઇન ઉપલબ્ધ છે. આ પ્લગઇન તમને કોડ લખતી વખતે મદદરૂપ થાય છે અને compiler તરફથી મળતી ભૂલો અને ચેતવણીઓ દર્શાવે છે. તમે જે સંપાદક (editor) અથવા આદર્શ (IDE) પસંદ કરો છો, તે તમારી કાર્યક્ષમતામાં વધારો કરી શકે છે અને Rust શીખવામાં તમને મદદરૂપ થઈ શકે છે.

આ પુસ્તક એ ધારણા કરતું નથી કે તમે Rust કોડ લખવા માટે કયા સાધનો વાપરો છો. લગભગ કોઈપણ ટેક્સ્ટ સંપાદક કાર્ય પૂર્ણ કરી શકે છે! જોકે, ઘણા ટેક્સ્ટ સંપાદકો અને સંકલિત વિકાસ પર્યાવરણો (IDEs) માં Rust માટે બનેલું સમર્થન હોય છે. તમે હંમેશાં Rust વેબસાઇટ પરના સાધનો પાનાં પર ઘણા સંપાદકો અને IDEsની પ્રમાણમાં વર્તમાન યાદી શોધી શકો છો.

આ પુસ્તક સાથે ઓફલાઈન કાર્ય કરવું.

ઘણી ઉદાહરણોમાં, આપણે પ્રમાણભૂત લાયબ્રેરીથી આગળના Rust પેકેજોનો ઉપયોગ કરીશું. તે ઉદાહરણો દ્વારા કાર્ય કરવા માટે, તમારે ઇન્ટરનેટ કનેક્શનની જરૂર પડશે અથવા તો નિર્ભારીતાઓને અગાઉથી ડાઉનલોડ કરવાની રહેશે. નિર્ભારીતાઓને અગાઉથી ડાઉનલોડ કરવા માટે, તમે નીચેના આદેશો ચલાવી શકો છો. (અમે cargo શું છે અને આ દરેક આદેશો શું કરે છે તે પછીથી વિગતવાર સમજાવીશું.)

$ cargo new get-dependencies $ cd get-dependencies $ cargo add rand@0.8.5 trpl@0.2.0 આ ક્રિયાક્રમ આ પેકેજો માટે ડાઉનલોડ્સને કેશ કરશે, જેથી તમારે ભવિષ્યમાં તેમને ફરીથી ડાઉનલોડ કરવાની જરૂર નહીં પડે. એકવાર તમે આ આદેશ ચલાવી લો, પછી તમારે get-dependencies ફોલ્ડર રાખવાની જરૂર નથી. જો તમે આ આદેશ ચલાવ્યો હોય, તો પુસ્તકના બાકીના ભાગમાં બધા cargo આદેશો સાથે --offline ધ્વજ વાપરી શકો છો, જેથી નેટવર્કનો ઉપયોગ કરવાનો પ્રયાસ કરવાને બદલે આ કેશ્ડ સંસ્કરણોનો ઉપયોગ કરી શકાય.

નોંધ: આ પુસ્તક કમાન્ડ લાઇનથી પૂર્વપરિચય હોવાનું માની લે છે. Rust તમારા સંપાદન અથવા સાધનો વિશે કે તમારો કોડ ક્યાં રહે છે તે વિશે કોઈ ચોક્કસ માંગણી કરતું નથી, તેથી જો તમે કમાન્ડ લાઇનને બદલે IDE વાપરવાનું પસંદ કરો છો, તો તમારા મનપસંદ IDE નો ઉપયોગ કરવા નિઃસંકોચ રહો. ઘણા IDEs હવે Rust માટે અમુક અંશે સમર્થન ધરાવે છે; વિગતો માટે IDE ના દસ્તાવેજો તપાસો. Rust ટીમ rust-analyzer દ્વારા મહાન IDE સમર્થનને સક્ષમ કરવા પર ધ્યાન કેન્દ્રિત કરી રહી છે. વધુ વિગતો માટે Appendix D જુઓ.

પ્રોજેક્ટ ડિરેક્ટરી સ્થાપન

તમે પ્રથમ તમારા Rust કોડને સંગ્રહિત કરવા માટે એક ડિરેક્ટરી બનાવશો. Rust ને તમારા કોડ ક્યાં રહે છે એ મહત્વનું નથી, પરંતુ આ પુસ્તકમાં આપેલ કસરતો અને પ્રોજેક્ટ્સ માટે, અમે તમારા હોમ ડિરેક્ટરીમાં projects નામની ડિરેક્ટરી બનાવવા અને તમારા બધા પ્રોજેક્ટ્સ ત્યાં રાખવાની

ભલામણ કરીએ છીએ. એક ટર્મિનલ ખોલો અને projects ડિરેક્ટરી અને “Hello, world!” પ્રોજેક્ટ માટે એક ડિરેક્ટરી બનાવવા માટે નીચેના આદેશો દાખલ કરો. Linux, macOS,

અને Windows પર PowerShell માટે, આ દાખલ કરો:

$ mkdir ~/projects $ cd ~/projects $ mkdir hello_world $ cd hello_world વિન્ડોઝ CMD માટે, આ દાખલ કરો:

mkdir “%USERPROFILE%\projects” cd /d “%USERPROFILE%\projects” mkdir hello_world cd hello_world

રસ્ટ પ્રોગ્રામની મૂળભૂત બાબતો આ પ્રકરણમાં, તમે રસ્ટ પ્રોગ્રામના મૂળભૂત ઘટકો વિશે શીખશો. દરેક રસ્ટ પ્રોગ્રામ main નામનું એક કાર્ય ધરાવે છે. આ કાર્ય એ છે જ્યાં પ્રોગ્રામનો અમલ શરૂ થાય છે. અહીં એક સરળ રસ્ટ પ્રોગ્રામનું ઉદાહરણ આપેલું છે: rust fn main() { println!("Hello, world!"); } આ પ્રોગ્રામ Hello, world! શબ્દમાળાને કન્સોલ પર છાપે છે. ચાલો આ પ્રોગ્રામના દરેક ભાગને સમજીએ. fn કીવર્ડનો ઉપયોગ એક નવું કાર્ય વ્યાખ્યાયિત કરવા માટે થાય છે. main એ કાર્યનું નામ છે. () કૌંસ સૂચવે છે કે આ કાર્ય કોઈ દલીલો સ્વીકારતું નથી. {} બ્લોક કાર્યના કોડને સમાવે છે. println! એ એક મેક્રો છે જે આપેલ શબ્દમાળાને કન્સોલ પર છાપે છે. ! સૂચવે છે કે આ એક મેક્રો છે, કાર્ય નથી. આ પ્રોગ્રામને ચલાવવા માટે, તેને ફાઇલ તરીકે સાચવો, ઉદાહરણ તરીકે main.rs, અને પછી તમારા ટર્મિનલમાં નીચેનો આદેશ ચલાવો: rustc main.rs આ એક એક્ઝિક્યુટેબલ ફાઇલ બનાવશે જેને તમે ચલાવી શકો છો. તમે rustup નો ઉપયોગ કરીને રસ્ટ ઇન્સ્ટોલ કરી શકો છો. cargo એ રસ્ટનું પેકેજ મેનેજર છે, જેનો ઉપયોગ પ્રોજેક્ટ બનાવવા અને સંચાલિત કરવા માટે થાય છે. સંકલક (compiler) તમારા કોડને મશીન કોડમાં ફેરવે છે, જ્યારે લિંકર (linker) વિવિધ ક્રેટ્સ (crates) ને એકસાથે જોડીને એક્ઝિક્યુટેબલ બનાવે છે.

ત્યારબાદ, એક નવી સ્ત્રોત ફાઈલ બનાવો અને તેને main.rs નામ આપો. Rust ફાઈલો હંમેશાં .rs એક્સ્ટેન્શન સાથે સમાપ્ત થાય છે. જો તમે તમારી ફાઇલનામમાં એક કરતાં વધુ શબ્દનો ઉપયોગ કરી રહ્યા છો, તો સંમેલન મુજબ તેમને અન્ડરસ્કોરથી અલગ કરો. ઉદાહરણ તરીકે, hello_world.rs નો ઉપયોગ કરોhelloworld.rs ને બદલે.

હવે તમે બનાવેલી main.rs ફાઈલ ખોલો અને લિસ્ટિંગ 1-1 માં આપેલ કોડ દાખલ કરો.

fn main() { println!("Hello, world!"); } ફાઈલને સાચવો અને તમારા ટર્મિનલ વિન્ડોમાં પાછા જાઓ જે ~/projects/hello_world ડિરેક્ટરીમાં છે. લિનક્સ અથવા મેકઓએસ પર, ફાઈલને સંકલિત કરવા (compile) અને ચલાવવા માટે નીચેના આદેશો દાખલ કરો:

$ rustc main.rs $ ./main Hello, world! વિન્ડોઝ પર, આદેશ .\main દાખલ કરો, ‎./main ને બદલે.

rustc main.rs .\main Hello, world! તમારા ઓપરેટિંગ સિસ્ટમ ગમે તે હોય, શબ્દમાળા Hello, world! ટર્મિનલ પર છાપાવા જોઈએ. જો તમને આ પરિણામ ન દેખાય, તો સ્થાપન વિભાગના “મુશ્કેલીનિવારણ” ભાગમાં મદદ મેળવવા માટેની રીતો જુઓ.

જો Hello, world! છાપાયું હોય, તો અભિનંદન! તમે સત્તાવાર રીતે એક Rust કાર્ય લખ્યું છે. એ તમને એક Rust પ્રોગ્રામર બનાવે છે—સ્વાગત છે!

ચાલો આ “હેલ્લો, વર્લ્ડ!” કાર્યક્રમને વિગતવાર જોઈએ. અહીં કોયડાનો પહેલો ભાગ છે:

fn main() {

} આ લીટીઓ એક કાર્ય વ્યાખ્યાયિત કરે છે જેનું નામ main છે. main કાર્ય વિશેષ છે: તે દરેક ચલાવવા યોગ્ય Rust કાર્યક્રમમાં પ્રથમ કોડ તરીકે ચાલે છે. અહીં, પ્રથમ લીટી એક કાર્ય જાહેર કરે છે જેનું નામ main છે જે કોઈ પરિમાણો ધરાવતું નથી અને કંઈપણ પરત કરતું નથી. જો પરિમાણો હોત, તો તે કૌંસની અંદર ( () ) જશે.

કાર્ય શરીર {} માં લપટેલું છે. Rust ને તમામ કાર્ય શરીરોને કર્લી બ્રેકેટની આસપાસ આવશ્યક છે. કાર્ય ઘોષણાની સમાન લીટી પર ખૂલતું કર્લી બ્રેકેટ મૂકવું એ સારી શૈલી છે, તેમની વચ્ચે એક જગ્યા ઉમેરવી.

નોંધ: જો તમે બધાં Rust પ્રોજેક્ટમાં એકસમાન શૈલી જાળવવા માંગતા હો, તો તમે rustfmt નામનું આપોઆપ ફોર્મેટિંગ સાધન વાપરી શકો છો જે તમારા કોડને ચોક્કસ શૈલીમાં ફોર્મેટ કરે છે (વધુ માહિતી rustfmt વિશે Appendix D માં મળશે). Rust ટીમ આ સાધન સ્ટાન્ડર્ડ Rust વિતરણ સાથે સામેલ કર્યું છે, જેમ કે rustc, તેથી તે પહેલાથી જ તમારા કમ્પ્યુટર પર ઇન્સ્ટોલ થયેલ હોવું જોઈએ!

main કાર્યનો મુખ્ય ભાગ નીચેના કોડ ધરાવે છે:

println!(“Hello, world!”); આ લીટી આ નાનકડા કાર્યક્રમમાં બધું જ કાર્ય કરે છે: તે છબી પર લખાણ છાપે છે. અહીં ત્રણ મહત્વપૂર્ણ વિગતો ધ્યાન રાખવા જેવી છે.

પ્રથમ, println! એક Rust મેક્રોને બોલાવે છે. જો તેના બદલે કોઈ કાર્ય બોલાવવામાં આવ્યું હોત, તો તેને println ( ! વગર) તરીકે દાખલ કરવામાં આવતું હોત. Rust મેક્રો એ કોડ લખવાનો એક માર્ગ છે જે Rust વાક્યરચનાને વિસ્તારવા માટે કોડ જનરેટ કરે છે, અને આપણે તેના વિશે પ્રકરણ ૨૦ માં વધુ વિગતવાર ચર્ચા કરીશું. અત્યારે, તમારે ફક્ત એટલું જાણવું જરૂરી છે કે ! નો ઉપયોગ કરવો એ સામાન્ય કાર્યને બદલે મેક્રોને બોલાવવાનો અર્થ થાય છે અને મેક્રો કાર્યો જેટલા નિયમોનું પાલન કરતા નથી.

બીજું, તમે "Hello, world!" શબ્દમાળા જુઓ છો. અમે આ શબ્દમાળાને println! ને દલીલ તરીકે પસાર કરીએ છીએ, અને શબ્દમાળા દેખાવમાં છપાય છે. ત્રીજું, અમે લીટીને

અર્ધવિરામચિહ્ન ( ; ) સાથે સમાપ્ત કરીએ છીએ, જે દર્શાવે છે કે આ અભિવ્યક્તિ પૂર્ણ થઈ ગઈ છે, અને આગલી શરૂ થવા માટે તૈયાર છે. મોટાભાગની Rust કોડની લીટીઓ અર્ધવિરામચિહ્ન સાથે સમાપ્ત થાય છે.

સંકલન અને અમલ જ્યારે તમે rustc આદેશ વાપરો છો, ત્યારે સંકલક તમારા સ્રોત કોડને મશીન કોડમાં ફેરવે છે. આ પ્રક્રિયામાં ઘણાં તબક્કાઓ શામેલ હોય છે, જેમાં તપાસણી, વિસ્તરણ અને કોડ નિર્માણનો સમાવેશ થાય છે. સંકલન પછી, લિંકર ઑબ્જેક્ટ ફાઇલોને એકસાથે જોડીને એક્ઝિક્યુટેબલ ફાઇલ બનાવે છે. આ ફાઇલમાં તમારા પ્રોગ્રામ માટે જરૂરી તમામ કોડ હોય છે. cargo run આદેશ સંકલન અને અમલ બંને કરે છે. જો સ્રોત કોડ પહેલેથી જ સંકલિત થયેલ હોય, તો લિંકર ફક્ત ઑબ્જેક્ટ ફાઇલોને જોડીને એક્ઝિક્યુટેબલ ફાઇલ બનાવશે. પછી, સિસ્ટમ એક્ઝિક્યુટેબલ ફાઇલ ચલાવે છે. જો તમે cargo build વાપરી રહ્યા છો, તો તે માત્ર સંકલન કરે છે અને એક્ઝિક્યુટેબલ ફાઇલ બનાવે છે, પરંતુ તેને ચલાવતું નથી. તમારે તેને ચલાવવા માટે cargo run નો ઉપયોગ કરવો પડશે. સંકલન પ્રક્રિયા દરમિયાન, સંકલક તમારા કોડમાં રહેલી ભૂલોને શોધી કાઢે છે. આ ભૂલોમાં પ્રકારની અસંગતતા, વ્યાકરણની ભૂલો અને સલામતીના ઉલ્લંઘનો શામેલ હોઈ શકે છે. જો સંકલકમાં કોઈ ભૂલ જણાય, તો તે તમને ચેતવણી આપશે અને સંકલન પ્રક્રિયા બંધ કરી દેશે. એકવાર તમારો કોડ સફળતાપૂર્વક સંકલિત થઈ જાય, પછી તમે તેને ચલાવી શકો છો. જ્યારે પ્રોગ્રામ ચાલે છે, ત્યારે તે સ્મૃતિમાં કોડ અને ડેટા લોડ કરે છે. પછી, પ્રોસેસર કોડના નિર્દેશોને એક પછી એક એક્ઝિક્યુટ કરે છે.

તમે હમણાં જ એક નવું બનાવેલું કાર્ય ચલાવ્યું છે, તેથી ચાલો પ્રક્રિયાના દરેક તબક્કાની તપાસ કરીએ.

Rust કાર્ય ચલાવતા પહેલાં, તમારે તેને Rust સંકલકનો ઉપયોગ કરીને સંકલિત કરવું આવશ્યક છે, જેમાં rustc આદેશ દાખલ કરવો અને તમારા સ્ત્રોત ફાઇલનું નામ પસાર કરવું જરૂરી છે, જેમ કે આ:

$ rustc main.rs જો તમને C અથવા C++ નો અનુભવ હોય, તો તમે નોંધશો કે આ gcc અથવા clang જેવું જ છે. સફળતાપૂર્વક સંકલન કર્યા પછી, Rust એક દ્વિસંગી ચલાવવા યોગ્ય ફાઇલ ઉત્પન્ન

કરે છે. Linux, macOS અને Windows પર PowerShell માં, તમે તમારા શેલમાં ls આદેશ દાખલ કરીને ચલાવવા યોગ્ય ફાઇલ જોઈ શકો છો:

$ ls main main.rs લિનક્સ અને મેકઓએસ પર, તમને બે ફાઇલો દેખાશે. વિન્ડોઝ પર પાવરશેલ સાથે, તમને એ જ ત્રણ ફાઇલો દેખાશે જે તમે CMD નો ઉપયોગ કરીને જોશો. વિન્ડોઝ પર CMD સાથે, તમે નીચે મુજબ દાખલ કરશો:

dir /B %= the /B option says to only show the file names =% main.exe main.pdb main.rs આ .rs એક્સ્ટેંશનવાળી સ્ત્રોત કોડ ફાઇલ, ચલાવવા યોગ્ય ફાઇલ (Windows પર main.exe, પરંતુ અન્ય તમામ પ્લેટફોર્મ પર main), અને Windows વાપરતી વખતે, ડિબગીંગ માહિતી ધરાવતી .pdb એક્સ્ટેંશનવાળી ફાઇલ દર્શાવે છે. અહીંથી, તમે main અથવા main.exe ફાઇલ ચલાવો છો, આ રીતે:

$ ./main # or .\main on Windows જો તમારી main.rs ફાઇલ તમારી “Hello, world!” કાર્યક્રમ છે, તો આ લીટી તમારા ટર્મિનલ પર Hello, world! છાપે છે.

જો તમે ગતિશીલ ભાષા (dynamic language) જેમ કે રૂબી, પાયથોન અથવા જાવાસ્ક્રિપ્ટથી વધુ પરિચિત છો, તો તમને એક કાર્યક્રમને અલગ પગલાં તરીકે સંકલિત (compile) અને ચલાવવાની આદત ન હોઈ શકે. Rust એ ahead-of-time સંકલિત ભાષા છે, જેનો અર્થ થાય છે કે તમે એક કાર્યક્રમનું સંકલન કરી શકો છો અને તે ચલાવવા યોગ્ય ફાઇલ કોઈ બીજાને આપી શકો છો, અને તેઓ Rust ઇન્સ્ટોલ કર્યા વિના પણ તેને ચલાવી શકે છે. જો તમે કોઈને .rb , .py , અથવા .js ફાઇલ આપો, તો તેમને રૂબી, પાયથોન અથવા જાવાસ્ક્રિપ્ટ અમલીકરણ (implementation) ઇન્સ્ટોલ કરવું જરૂરી છે (ક્રમશઃ). પરંતુ તે ભાષાઓમાં, તમારે તમારા કાર્યક્રમને સંકલિત અને ચલાવવા માટે ફક્ત એક જ આદેશની જરૂર પડે છે. ભાષા ડિઝાઇન (language design) માં બધું જ આપ-લે (trade-off) છે.

ફક્ત rustc સાથે સંકલન કરવું સરળ કાર્યક્રમો માટે ઠીક છે, પરંતુ જેમ જેમ તમારું પ્રોજેક્ટ વધે તેમ, તમારે બધા વિકલ્પોનું વ્યવસ્થાપન કરવું અને તમારા કોડને વહેંચવાનું સરળ બનાવવું પડશે. હવે પછી, અમે તમને Cargo સાધનથી પરિચિત કરાવશું, જે તમને વાસ્તવિક દુનિયાના Rust કાર્યક્રમો લખવામાં મદદ કરશે.

Hello, Cargo!

નમસ્તે, ક્રેટ!

Cargo એ Rustનું નિર્માણ તંત્ર અને પેકેજ વ્યવસ્થાપક છે. મોટાભાગના Rustaceans આ સાધનનો ઉપયોગ તેમના Rust પ્રોજેક્ટ્સનું સંચાલન કરવા માટે કરે છે, કારણ કે Cargo તમારા માટે ઘણાં કાર્યો સંભાળે છે, જેમ કે તમારા કોડનું નિર્માણ કરવું, તમારા કોડને જરૂરી હોય તેવા પુસ્તકાલયો (libraries) ડાઉનલોડ કરવા અને તે પુસ્તકાલયોનું નિર્માણ કરવું. (જે પુસ્તકાલયો તમારા કોડને જરૂર હોય છે તેને આપણે આધારભૂત (dependencies) કહીએ છીએ.)

આપણે અત્યાર સુધી જે સરળ Rust કાર્યક્રમો લખ્યા છે, તેમાં કોઈ આધારભૂત નથી. જો આપણે “Hello, world!” પ્રોજેક્ટ Cargo સાથે બનાવ્યો હોત, તો તે ફક્ત Cargoના તે ભાગનો ઉપયોગ કરત જે તમારા કોડનું નિર્માણ કરે છે. જેમ જેમ તમે વધુ જટિલ Rust કાર્યક્રમો લખશો, તેમ તેમ તમારે આધારભૂત ઉમેરવા પડશે અને જો તમે Cargoથી શરૂ કરીને કોઈ પ્રોજેક્ટ કરો છો, તો આધારભૂત ઉમેરવાનું ઘણું સરળ રહેશે.

કારણ કે મોટાભાગના Rust પ્રોજેક્ટ્સમાં Cargo વપરાય છે, આ પુસ્તકના બાકીના ભાગમાં એવું માનવામાં આવે છે કે તમે પણ Cargo વાપરી રહ્યા છો. જો તમે સત્તાવાર સ્થાપકોનો ઉપયોગ કર્યો હોય, તો Cargo Rust સાથે જ ઇન્સ્ટોલ થઈ જાય છે, જે “સ્થાપન” વિભાગમાં ચર્ચા કરવામાં આવી છે. જો તમે અન્ય કોઈ રીતે Rust સ્થાપિત કર્યું હોય, તો તમારા ટર્મિનલમાં નીચે મુજબ દાખલ કરીને તપાસ કરો:

$ cargo –version જો તમને આવૃત્તિ સંખ્યા દેખાય છે, તો તમારી પાસે તે છે! જો તમને કોઈ ભૂલ દેખાય છે, જેમ કે command not found, તો તમારા સ્થાપન પદ્ધતિ માટેના દસ્તાવેજો જુઓ જેથી કરીને કાર્ગોને અલગથી કેવી રીતે સ્થાપિત કરવું તે નક્કી કરી શકાય.

ક્રેટ સાથે પ્રોજેક્ટ બનાવવો cargo new <project_name> આદેશનો ઉપયોગ કરીને નવો ક્રેટ બનાવો. આ એક નવી ડિરેક્ટરી બનાવશે જે તમારા પ્રોજેક્ટનું નામ હશે. ઉદાહરણ તરીકે, “hello-world” નામનો પ્રોજેક્ટ બનાવવા માટે: cargo new hello-world આ આદેશ hello-world નામની ડિરેક્ટરી બનાવશે અને તેમાં જરૂરી ફાઇલો અને ફોલ્ડર્સ ઉત્પન્ન કરશે. તમે પછી ડિરેક્ટરીમાં જઈ શકો છો: cd hello-world હવે, તમે તમારા પ્રોજેક્ટના સ્ત્રોત કોડને src/main.rs ફાઇલમાં લખી શકો છો. cargo આપોઆપ જરૂરી ફાઇલ માળખું સેટ કરશે. તમે cargo build આદેશનો ઉપયોગ કરીને તમારા પ્રોજેક્ટને બનાવી શકો છો, અને cargo run આદેશનો ઉપયોગ કરીને ચલાવી શકો છો. જો કોઈ ભૂલ હોય, તો cargo તમને ચેતવણી આપશે.

ચાલો, કાર્ગોનો ઉપયોગ કરીને એક નવું પ્રોજેક્ટ બનાવીએ અને જોઈએ કે તે આપણી મૂળ “Hello, world!” પ્રોજેક્ટથી કેવી રીતે અલગ છે. તમારા પ્રોજેક્ટ્સ ડિરેક્ટરીમાં પાછા જાઓ (અથવા તમે તમારો કોડ ક્યાં સંગ્રહિત કરવાનું નક્કી કર્યું હોય ત્યાં). પછી, કોઈપણ ઓપરેટિંગ સિસ્ટમ પર, નીચે મુજબ ચલાવો:

$ cargo new hello_cargo $ cd hello_cargo પ્રથમ આદેશ એક નવું સંકેતક અને પ્રોજેક્ટ બનાવે છે જેનું નામ hello_cargo છે. આપણે આપણા પ્રોજેક્ટને hello_cargo નામ આપ્યું છે, અને Cargo તેનાં ફાઈલો એ જ નામના સંકેતકમાં બનાવે છે. hello_cargo

સંકેતકમાં જાઓ અને ફાઈલોની યાદી જુઓ. તમને દેખાશે કે Cargo એ આપણી માટે બે ફાઈલો અને એક સંકેતક ઉત્પન્ન કર્યો છે: એક Cargo.toml ફાઈલ અને એક src સંકેતક જેમાં main.rs ફાઈલ અંદર છે. તેણે એક

નવું Git ભંડાર પણ શરૂ કર્યું છે સાથે સાથે એક .gitignore ફાઈલનું. જો તમે cargo new આદેશનો ઉપયોગ વર્તમાન Git ભંડારમાં કરો છો, તો Git ફાઈલો ઉત્પન્ન થશે નહીં; તમે આ વર્તનને cargo new --vcs=git નો ઉપયોગ કરીને બદલી શકો છો.

નોંધ: Git એક સામાન્ય વર્ઝન નિયંત્રણ પ્રણાલી છે. તમે cargo new ને અન્ય વર્ઝન નિયંત્રણ પ્રણાલી અથવા કોઈ વર્ઝન નિયંત્રણ પ્રણાલી વાપરવા માટે --vcs ધ્વજ (flag) નો ઉપયોગ કરીને બદલી શકો છો. ઉપલબ્ધ વિકલ્પો જોવા માટે `cargo

new –help` ચલાવો. તમારી પસંદગીના ટેક્સ્ટ સંપાદકમાં Cargo.toml ખોલો. તે યાદી 1-2 માં આપેલ કોડ જેવું દેખાશે.

[package] name = "hello_cargo" version = "0.1.0" edition = "2024"

[dependencies] આ ફાઈલ TOML ( ટોમ્સ ઓબ્વિયસ, મિનિમલ ભાષા ) ફોર્મેટમાં છે, જે Cargo નું રૂપરેખાંકન ફોર્મેટ છે.

પ્રથમ લીટી, [package] , એક વિભાગનું નામ છે જે દર્શાવે છે કે નીચેના વિધાનો એક ક્રેટને રૂપરેખાંકિત કરી રહ્યા છે. જેમ આપણે આ ફાઈલમાં વધુ માહિતી ઉમેરીશું, તેમ તેમ અમે અન્ય વિભાગો પણ ઉમેરીશું.

આગામી ત્રણ લીટીઓ Cargo ને તમારા કાર્યક્રમને સંકલન કરવા માટે જરૂરી રૂપરેખાંકન માહિતી સેટ કરે છે: નામ, આવૃત્તિ અને ઉપયોગ કરવાના Rust નું આવૃત્તિ. આપણે edition કી વિશે Appendix E માં વાત કરીશું.

છેલ્લી લીટી, [dependencies] , એ એક વિભાગની શરૂઆત છે જ્યાં તમે તમારા પ્રોજેક્ટની નિર્ભરતાઓની યાદી આપી શકો છો. Rust માં, કોડના પેકેજોને ક્રેટ કહેવામાં આવે છે. આ પ્રોજેક્ટ માટે આપણને અન્ય કોઈ ક્રેટની જરૂર નથી, પરંતુ બીજા પ્રકરણમાં પ્રથમ પ્રોજેક્ટ માટે જરૂર પડશે, તેથી આપણે તે સમયે આ નિર્ભરતા વિભાગનો ઉપયોગ કરીશું.

હવે src/main.rs ખોલો અને એક નજર નાખો:

ફાઈલનું નામ: src/main.rs

fn main() { println!(“Hello, world!”); } કર્ગોએ તમારા માટે “Hello, world!” કાર્યક્રમ ઉત્પન્ન કર્યો છે, જેListing 1-1માં આપણે લખ્યો હતો તેના જેવો જ છે! અત્યાર સુધી, આપણા પ્રોજેક્ટ અને કર્ગોએ ઉત્પન્ન કરેલા પ્રોજેક્ટ વચ્ચેનો તફાવત એ છે કે કર્ગોએ કોડને src ડિરેક્ટરીમાં મૂક્યો છે, અને આપણી પાસે ટોચની ડિરેક્ટરીમાં Cargo.toml રૂપરેખાંકન ફાઇલ છે.

કર્ગો તમારા સ્રોત ફાઇલોને src ડિરેક્ટરીમાં રહેવાની અપેક્ષા રાખે છે. ટોચ-સ્તરના પ્રોજેક્ટ ડિરેક્ટરી ફક્ત README ફાઇલો, લાયસન્સ માહિતી, રૂપરેખાંકન ફાઇલો અને તમારા કોડ સાથે સંબંધિત ન હોય તેવી અન્ય વસ્તુઓ માટે છે. કર્ગોનો ઉપયોગ તમને તમારા પ્રોજેક્ટને ગોઠવવામાં મદદ કરે છે. દરેક વસ્તુ માટે એક સ્થાન છે, અને દરેક વસ્તુ તેની જગ્યાએ છે.

જો તમે એવી કોઈ યોજના શરૂ કરી હોય જે Cargo વાપરતી નથી, જેમ કે આપણે “Hello, world!” યોજનામાં કર્યું હતું, તો તમે તેને Cargo વાપરતી યોજનામાં ફેરવી શકો છો. તમારા યોજનાના કોડને src ડિરેક્ટરીમાં ખસેડો અને એક યોગ્ય Cargo.toml ફાઈલ બનાવો. આ Cargo.toml ફાઈલ મેળવવાનો એક સરળ રસ્તો એ છે કે cargo init ચલાવવું, જે આપમેળે તેને બનાવી દેશે.

ક્રેટ પ્રોજેક્ટનું નિર્માણ અને ચલાવીશઃ cargo નો ઉપયોગ કરીને, તમે તમારા પ્રોજેક્ટને સરળતાથી બનાવી અને ચલાવી શકો છો. rustup ઇન્સ્ટોલ કર્યા પછી, cargo આપમેળે જ ઇન્સ્ટોલ થઈ જાય છે. પ્રોજેક્ટ બનાવવા માટે, આદેશ વાપરો: cargo build આ આદેશ તમારા પ્રોજેક્ટના સ્ત્રોત કોડને સંકલિત (compile) કરે છે અને એક્ઝિક્યુટેબલ ફાઈલ બનાવે છે. સંકલન (compilation) દરમિયાન કોઈ ભૂલ (error) આવે તો, cargo તમને વિગતવાર માહિતી આપશે. પ્રોજેક્ટ ચલાવવા માટે, આ આદેશ વાપરો: cargo run આ આદેશ તમારા પ્રોજેક્ટને સંકલિત (compile) કરે છે અને પછી એક્ઝિક્યુટેબલ ફાઈલને ચલાવે છે. તમે cargo check આદેશનો ઉપયોગ કરીને ફક્ત સ્ત્રોત કોડની ચકાસણી પણ કરી શકો છો, જે ઝડપી છે કારણ કે તે એક્ઝિક્યુટેબલ ફાઈલ બનાવતું નથી. આ ખાસ કરીને મોટા પ્રોજેક્ટમાં ઉપયોગી છે. જો તમે કસોટીઓ (tests) ચલાવવા માંગતા હો, તો આ આદેશ વાપરો: cargo test cargo તમારા પ્રોજેક્ટની અંદર રહેલી તમામ કસોટીઓ (tests) શોધે છે અને તેમને ચલાવે છે. કસોટીઓના પરિણામો તમને દર્શાવવામાં આવશે, જેમાં કોઈ નિષ્ફળતા (failures) અથવા ચેતવણીઓ (warnings) શામેલ હોઈ શકે છે.

હવે આપણે જોઈએ કે જ્યારે આપણે Cargo વડે “Hello, world!” કાર્યક્રમ બનાવીએ અને ચલાવીએ ત્યારે શું ફેરફાર થાય છે. તમારા hello_cargo ફોલ્ડરથી, નીચેનો આદેશ દાખલ કરીને તમારી યોજના બનાવો:

$ cargo build Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo) Finished dev [unoptimized + debuginfo] target(s) in 2.85 secs આ આદેશ target/debug/hello_cargo (અથવા Windows પર target\debug\hello_cargo.exe) માં એક ચલાવવા યોગ્ય ફાઈલ બનાવે છે, તમારા વર્તમાન ડિરેક્ટરીમાં નહીં. કારણ કે ડિફૉલ્ટ બિલ્ડ એ ડીબગ બિલ્ડ છે, Cargo દ્વિસંગીને debug નામની ડિરેક્ટરીમાં મૂકે છે. તમે આ આદેશ સાથે ચલાવવા યોગ્ય ફાઈલ ચલાવી શકો છો:

$ ./target/debug/hello_cargo # or .\target\debug\hello_cargo.exe on Windows Hello, world! જો બધું સારું ચાલશે, તો Hello, world! ટર્મિનલ પર છાપાઈ જવું જોઈએ. પ્રથમ વખત cargo build ચલાવવાથી Cargo એક નવી ફાઈલ ટોચના સ્તરે બનાવે છે: Cargo.lock . આ ફાઈલ તમારા પ્રોજેક્ટમાં રહેલા આધારભૂત (dependencies) ઘટકોના ચોક્કસ સંસ્કરણોનો રેકોર્ડ રાખે છે. આ પ્રોજેક્ટમાં કોઈ આધારભૂત ઘટકો નથી, તેથી ફાઈલ થોડી ખાલી છે. તમારે ક્યારેય પણ આ ફાઈલ જાતે બદલવાની જરૂર નહીં પડે; Cargo તેના વિષમ પાત્રોનું વ્યવસ્થાપન તમારા માટે કરે છે.

અમે cargo build સાથે એક પ્રોજેક્ટ બનાવ્યો અને ./target/debug/hello_cargo વડે ચલાવ્યો, પરંતુ અમે cargo run નો ઉપયોગ કરીને કોડને સંકલિત (compile) કરી શકીએ છીએ અને પછી એક જ આદેશમાં પરિણામી એક્ઝિક્યુટેબલ ચલાવી શકીએ છીએ:

$ cargo run Finished dev [unoptimized + debuginfo] target(s) in 0.0 secs Running target/debug/hello_cargo Hello, world! cargo run વાપરવું એ cargo build ચલાવવા અને પછી બાઈનરીનો આખો માર્ગ વાપરવા કરતાં વધુ અનુકૂળ છે, તેથી મોટાભાગના વિકાસકર્તાઓ cargo run વાપરે છે. ધ્યાન કરો કે આ વખતે

અમને આઉટપુટ દેખાયું ન હતું જે દર્શાવે છે કે Cargo hello_cargo સંકલન કરી રહ્યું હતું. Cargo એ નક્કી કર્યું કે ફાઇલો બદલાઈ નથી, તેથી તેણે ફરીથી બનાવ્યું નહીં પરંતુ ફક્ત બાઈનરી ચલાવ્યું. જો તમે તમારા સ્રોત કોડમાં ફેરફાર કર્યો હોત, તો Cargo પ્રોજેક્ટને ચલાવતા પહેલા ફરીથી બનાવ્યો હોત, અને તમને આ આઉટપુટ દેખાયું હોત:

$ cargo run Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo) Finished dev [unoptimized + debuginfo] target(s) in 0.33 secs Running target/debug/hello_cargo Hello, world! કાર્ગો cargo check નામની એક આદેશ પણ આપે છે. આ આદેશ ઝડપથી તમારા કોડની ચકાસણી કરે છે કે તે સંકલિત થાય છે કે નહીં, પરંતુ એક્ઝિક્યુટેબલ ઉત્પન્ન કરતો નથી.

$ cargo check Checking hello_cargo v0.1.0 (file:///projects/hello_cargo) Finished dev [unoptimized + debuginfo] target(s) in 0.32 secs તમે ચલાવવા યોગ્ય ફાઈલ નથી ઇચ્છતા કેમ? ઘણીવાર, cargo check એ cargo build કરતાં ઘણું ઝડપી હોય છે કારણ કે તે ચલાવવા યોગ્ય ફાઈલ બનાવવાની પ્રક્રિયાને છોડી દે છે. જો તમે કોડ લખતી વખતે સતત તમારા કાર્યની તપાસ કરતા હોવ, તો cargo check નો ઉપયોગ કરવાથી તમને ખબર પડશે કે તમારો પ્રોજેક્ટ હજી પણ સંકલિત થઈ રહ્યો છે કે નહીં, તે જાણવાની પ્રક્રિયા ઝડપી થશે! આથી, ઘણા Rustaceans તેમના પ્રોગ્રામ લખતી વખતે સમયાંતરે cargo check ચલાવે છે જેથી ખાતરી થાય કે તે સંકલિત થાય છે. પછી, તેઓ જ્યારે ચલાવવા યોગ્ય ફાઈલનો ઉપયોગ કરવા તૈયાર હોય ત્યારે cargo build ચલાવે છે.

ચાલો આપણે અત્યાર સુધીમાં કાર્ગો વિશે જે શીખ્યા તેનું પુનરાવર્તન કરીએ:

આપણે cargo run નો ઉપયોગ કરીને એક જ પગલામાં પ્રોજેક્ટ બનાવી અને ચલાવી શકીએ છીએ.

આપણે cargo check નો ઉપયોગ કરીને પ્રોજેક્ટ બનાવી શકીએ છીએ, જે બાઈનરી ઉત્પન્ન કર્યા વિના ભૂલો માટે તપાસ કરે છે.

આપણા કોડની જેમ જ ડિરેક્ટરીમાં બિલ્ડનું પરિણામ સાચવવાની જગ્યાએ, કાર્ગો તેને target/debug ડિરેક્ટરીમાં સંગ્રહિત કરે છે.

Cargo વાપરવાના અન્ય એક લાભ એ છે કે આદેશો તમે જે ઓપરેટિંગ સિસ્ટમ પર કાર્ય કરી રહ્યા છો તેનાથી કોઈ ફરક પડતો નથી. તેથી, હવે પછી અમે Linux અને macOSની સરખામણીમાં Windows માટે ખાસ સૂચનાઓ આપવાનું બંધ કરીશું.

રિલીઝ માટે નિર્માણ

જ્યારે તમારી યોજના અંતિમ મુકાબજા માટે તૈયાર હોય, ત્યારે તમે તેને સુધારાઓ સાથે સંકલિત કરવા માટે cargo build --release નો ઉપયોગ કરી શકો છો. આ આદેશ target/release માં એક ચલાકીય વસ્તુ બનાવશે, target/debug ને બદલે. સુધારાઓ તમારી Rust કોડને ઝડપી બનાવે છે, પરંતુ તેમને ચાલુ કરવાથી તમારા કાર્યક્રમને સંકલિત થવામાં લાગતો સમય વધે છે. તેથી જ ત્યાં બે અલગ-અલગ રૂપરેખાઓ છે: એક વિકાસ માટે, જ્યારે તમે ઝડપથી અને વારંવાર ફરીથી બનાવવાનું ઇચ્છો છો, અને બીજો અંતિમ કાર્યક્રમ બનાવવા માટે જે વપરાશકર્તાને આપવામાં આવશે અને તેને વારંવાર ફરીથી બનાવવામાં આવશે નહીં અને તે શક્ય તેટલી ઝડપથી ચાલશે. જો તમે તમારા કોડના ચાલવાના સમયનું મૂલ્યાંકન કરી રહ્યા હો, તો cargo build --release ચલાવવાનું અને target/release માં ચલાકીય વસ્તુ સાથે મૂલ્યાંકન કરવાનું સુનિશ્ચિત કરો.

કર્ગોના સંમેલનોનો ઉપયોગ કરવો.

સરળ પ્રોજેક્ટ્સ સાથે, Cargo માત્ર rustc વાપરવા કરતાં વધારે લાભ આપતું નથી, પરંતુ જ્યારે તમારા કાર્યક્રમો વધુ જટિલ બનશે ત્યારે તે પોતાની કિંમત સાબિત કરશે. એકવાર પ્રોગ્રામ્સ અનેક ફાઇલો સુધી પહોંચે અથવા કોઈ આધાર રાખતી વસ્તુની જરૂર પડે, ત્યારે Cargo દ્વારા નિર્માણનું સંકલન કરાવવું ઘણું સરળ બની જાય છે.

જો કે hello_cargo પ્રોજેક્ટ સરળ છે, છતાં તે હવે ઘણાં વાસ્તવિક સાધનોનો ઉપયોગ કરે છે જેનો તમે તમારા Rust કારકિર્દીના બાકીના ભાગમાં ઉપયોગ કરશો. હકીકતમાં, કોઈપણ હાલના પ્રોજેક્ટ્સ પર કામ કરવા માટે, તમે Git નો ઉપયોગ કરીને કોડ તપાસવા, તે પ્રોજેક્ટની ડિરેક્ટરીમાં જવાનું અને નિર્માણ કરવા માટે નીચેના આદેશોનો ઉપયોગ કરી શકો છો:

$ git clone example.org/someproject $ cd someproject $ cargo build વધુ માહિતી માટે, Cargo નું દસ્તાવેજીકરણ તપાસો.

સારાંશ

તમારા Rust પ્રવાસની શરૂઆત ખૂબ જ સારી રીતે થઈ છે! આ પ્રકરણમાં, તમે શીખ્યા કે કેવી રીતે:

rustup નો ઉપયોગ કરીને Rust નું નવીનતમ સ્થિર સંસ્કરણ સ્થાપિત કરવું.

નવા Rust સંસ્કરણ પર અપડેટ કરવું.

સ્થાનિક રીતે સ્થાપિત દસ્તાવેજો ખોલવા.

rustc દ્વારા સીધું જ “Hello, world!” કાર્યક્રમ લખવો અને ચલાવવો.

Cargo ના સંમેલનોનો ઉપયોગ કરીને નવો પ્રોજેક્ટ બનાવવો અને ચલાવવો.

હવે વધુ મજબૂત કાર્યક્રમ બનાવવાનો આ સારો સમય છે, જેથી Rust કોડ વાંચવાની અને લખવાની ટેવ પડે. તેથી, પ્રકરણ ૨ માં, આપણે એક અનુમાન લગાવવાની રમત (guessing game) નો કાર્યક્રમ બનાવીશું. જો તમે સામાન્ય પ્રોગ્રામિંગ ખ્યાલો Rust માં કેવી રીતે કાર્ય કરે છે તે શીખવા માટે શરૂઆત કરવા માંગતા હો, તો પ્રકરણ ૩ જુઓ અને પછી પ્રકરણ ૨ પર પાછા ફરો.
